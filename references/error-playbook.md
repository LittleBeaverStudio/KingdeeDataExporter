# 错误判读与自愈手册

> 原则：**先判读，再动手**。金蝶密码连续错约 5 次会锁账号 —— 任何情况下不得连续盲试密码超过 2 次。
> 第一步永远是 `python data_exporter.py --doctor`。

## 0. 万能兜底流程

1. 跑 `--doctor`，把**第一步失败**的那条提示直接照着做。
2. 报错原文完整保留给用户（不要转述丢失），再附上自愈建议。
3. 仍无法解决 → 明确告诉用户卡在哪一步、已排除什么、需要找谁（金蝶管理员 / 实施商），
   **不要假装成功**，也不要靠反复重试硬撞。

## 1. 接入类（配置阶段）

| 错误特征 | 根因 | 自愈动作 |
|---|---|---|
| 提示"未检测到可用的金蝶连接配置" | 三种配置来源都没读到 | 跑 `--help-config` 看配置方法；推荐写 `~/.workbuddy/kingdee/config.json`（技能目录之外，升级不覆盖） |
| `acct_name` 解析失败：不在账套列表里 | 账套名称写错，或该服务器上没有这个账套 | `--list-datacenters` 列出全部账套，复制**准确的完整名称**；列表为空说明地址指向的不是金蝶站点 |
| `acct_name` 匹配到多个 | 名称有重复前缀 | 配置文件里写完整名称，或直接填 acctid |

## 2. 网络与连接类

| 错误特征 | 根因 | 自愈动作 |
|---|---|---|
| `SSLError` / 证书不受信 | 地址 http/https 写错 | 用浏览器打开登录页，复制地址栏的完整 URL |
| `ConnectionError` / 连不上 | 服务器不在内网、需 VPN、或地址错 | 确认浏览器能否打开金蝶登录页 |
| HTTP **403** 且空响应 | URL 路径错（漏 `/k3cloud/`），或地址指向网关/WAF | 工具会自动补 `/k3cloud/`；仍 403 则确认不是被网关拦下 |
| HTTP **502 / 504** / `Tunnel connection failed` | 出口代理或网关**瞬时**故障（不是金蝶的问题） | 实测形态是"连错几次后成功"，隔一会儿重跑。反复失败则查代理配置 |
| 返回内容不是 JSON | 地址指向了非金蝶站点（或被重定向到网关页） | 核对 `base_url` 到底指向哪里 |

## 3. 登录类

| 错误特征 | 根因 | 自愈动作 |
|---|---|---|
| `MsgCode 11` +「当前用户未指定允许调用WebAPI接口」 | **WebAPI 白名单未配**（最高频、最易误判） | 见下方「白名单正确配置路径」。该参数 **fail-closed**：不在名单里必然被拦，与账号业务权限是否齐全无关 |
| `LoginResultType: -1` +「当前尝试登录的数据中心无法获取到」 | 账套 ID 错 | `--list-datacenters` 取正确 `Id`，或改用 `acct_name` |
| `CheckPasswordPolicy` /「用户名或密码错误」 | **账套已对**，是账号或密码错 | 查大小写（`Hg` ≠ `HG`）、首尾空格；**最多再试 2 次**，否则找用户确认 |
| 「会话信息已丢失，请重新登录」 | 会话过期 | 重新执行命令（每次运行都会重新登录） |
| 「没有权限」 | 账号缺模块权限 | 找管理员开通，或换有权限的取数账号 |

### 白名单正确配置路径（数据中心级参数）

```
基础管理 → 公共设置 → 参数设置 → 左侧【基础管理】→【BOS平台】→【WebAPI】
  → 「允许调用WebAPI接口用户」→ 加入取数账号 → 保存
```

- ⚠️ **不是**在「系统管理 → 用户管理」里勾选（常见误传）。
- 同页还有独立【白名单设置】：`可访问IP`（`;` 分隔，支持网段）/ `允许调用客户端` / `允许调用接口`。

## 4. 查询类

| 错误特征 | 根因 | 自愈动作 |
|---|---|---|
| `MsgCode 8`「接口参数 data 不能为空」 | 载荷格式错 | `ExecuteBillQuery` 的 `data` 必须是 **JSON 字符串**（传 dict 会报这个）；`QueryBusinessInfo` 用 `{"data": {"FormId": ...}}` |
| 「元数据中标识为 XXX 的字段不存在」 | 字段标识在当前账套不存在 | `--inspect-fields <FormId> --filter <关键字>` 核对权威清单 |
| 「当前查询串无法解析--XXX」 | 字段名语法错（用了中文名/点号） | 改用英文标识 |
| 「标识为"XXX"的业务对象不存在」 | FormId 错或拼错 | 对照 `--show-config` 清单；拼写极敏感 |
| 返回 `[[{"Result":...}]]`（元素是 dict 不是 list） | **服务端把错误包装成数据行返回，不抛异常** | 解析前必须过滤 dict 行；工具已内置检测 |
| 数量虚高（如物料数翻倍） | **多组织重复记录**或分录级展开 | 见 `query-cookbook.md` 去重口径 |
| 有单据但查不到数据 | 权限 / 字段可见性 / `SubSystemId` 许可 | 依次排查：过滤条件 → 字段可见性 → SubSystemId 许可 |
| 金额字段返回 `***` | 服务端脱敏（按单据类型/字段下发，且动态变化） | 换单据类型取价，或走税额反推 |

## 5. 导出结果类

| 现象 | 排查 |
|---|---|
| 某工作表有列但全空 | 该字段在当前账套为空，或字段名在该环境下映射不到 —— 用 `--inspect-fields` 核对 |
| 整个工作表 0 行 | 日期范围 / 组织编码 / 单据状态 / `--only` 名称，四者逐一放宽验证 |
| Excel 打不开 | 检查是否在导出过程中被中断；重跑一次 |
| 中文名参数在 Windows 控制台乱码 | 改用 `form_id` / 英文字段 key |

## 6. 明确做不到的事（不要浪费时间尝试）

| 想做的事 | 结论 |
|---|---|
| 查「当前处理人 / 待我审批」 | 不可能。不在元数据、无 `WF_*` 业务对象、无审批查询端点（13 个候选全 `no found.`）。`WorkflowAudit` 只**执行**审批，不**查询** |
| 查审批流程节点 / 提示原文 | 只在 UI 可见，WebAPI 读不到 |
| 用字段引用当过滤条件（`FCreatorId.FName='某人'`） | 报错。改用内码，或拉全量后本地过滤 |
